# Platform map brief

**Quick read:** The broader courses platform and its reading, RTL, assessment, and knowledge-graph requirements. Use for platform scope beyond the immediate factory.

Planning workflow references: `wayfinder` · `batch-grill-me` (optional workstation skills).

**The idea.** Build a courses platform — as simple as possible, but intuitive, rigorous, and practical. Lessons are Markdown files; MD is the canonical format for all teaching content. This map's destination: **platform v1 built and shippable**, with execution carried inside the map (Notes override wayfinder's "plan, don't do" default).

**Immediate delivery goal: Content Factory v1.** The current transcript pipeline is **v0**. Evolve it into a cost-effective content factory with Apple-grade quality control across the entire pipeline, from source ingestion to accepted, rendered lessons. The goal, review findings, acceptance criteria, and open decisions are defined in [content-factory-v1-goal.md](../factory/content-factory-v1-goal.md). The binding resolutions and outstanding proof for the blindspots are in [content-factory-v1-resolution.md](../factory/content-factory-v1-resolution.md). The broader platform destination remains as described here.

**Learner-platform v0 is static:** do not confuse this product boundary with the legacy transcript-pipeline label above. The learner-facing v0 has generated pages and browser-local enhancement only—no server-side application functions, runtime database, custom API, authentication, synced progress, server-processed forms, or runtime model calls. Practice and assessment are components inside lesson pages, not standalone product destinations. Private review and publication infrastructure remains outside the public learner runtime.

**Pedagogical thesis.** Learning is the incremental gain in your ability to perform a tangible, reproducible skill — you can't move knowledge into long-term memory by watching (after Justin Skycak, "When Does the Learning Happen?", 2024). So lessons are organized around **skills, not explanations**: each lesson names the skill it builds, and the practice is where the learning happens. Transcribed lectures are raw material, never the course itself.

**What already exists.** This repo's pipeline (Python/uv, yt-dlp, Gemini, Turso/SQLite, R2) contains raw transcripts, several processed variants, and metadata (xlsx files, `youtube-iug.db`, and multiple source/output layouts). The earlier **321-playlist** figure is historical: the local inventory contains **340 playlist metadata records**, which are not 340 accepted courses. Source IDs, membership aliases, and legacy completion evidence are reconciled in [content-factory-v1-inventory.md](../factory/content-factory-v1-inventory.md). The semi-processed data came from older, weaker LLMs — today's models are far better. **Current policy: rebuild v1 teaching artifacts from raw whisper JSON plus the matching cleaned `GeminiLongContext/` counterparts; use matching YouTube lectures only for needed diagrams.** Raw JSON remains canonical for segmentation and timestamps. Other generated outputs and completion flags remain audit-only, and no legacy artifact is a reason to skip this first pass. Resume/cache verified work produced by the new v1 process on later runs; do not import outside teaching material. The **Thmanyah font family** (Serif Text / Sans / Digital — bilingual Arabic/English, from font.thmanyah.com) is already downloaded in `~/Downloads` and is the house typeface.

**Fixed constraints** (settled — grill everything else):

1. **Apple-grade quality bar** for every feature and detail. Simplicity means edited scope, never shipped crudeness.
2. **RTL is first-class.** ~80% of the courses are Arabic: typography, layout, and mixed-direction text must be excellent in Arabic first, and equally solid in English.
3. **Lesson anatomy:** each lesson has clearly written "aha moment" passages and diagrams authored via the Excalidraw MCP server (keep editable sources, not just exports).
4. **Exceptional reading experience:** accessibility (WCAG-minded), comfortable long-form reading, flawless Thmanyah rendering. Reader chrome to meet the bar: Fanout's per-lesson sidebar tree with checkmarks and durations ([fanout-feature-analysis.md](../research/fanout-feature-analysis.md) §3.1) — client-side progress that survives static hosting.
5. **Inline assessment** embedded in the lesson MD — `cognitive-engineering-lab/mdbook-quiz` is the reference; evaluate alternatives and pick what fits the chosen stack. Questions sit at pedagogically correct points and are genuinely hard and engaging.
6. **Knowledge graph:** concept nodes + typed edges across the whole corpus, informed by current ontology practice. Every course and every lesson also gets an **openwiki** layer — evaluate Google's **Open Knowledge Format v0.2** (`GoogleCloudPlatform/knowledge-catalog`, `okf/SPEC.md`) as its representation. The UX bar is Fanout's Knowledge Topography ([fanout-feature-analysis.md](../research/fanout-feature-analysis.md) §3.3): a first-class destination page searchable over concepts, **aliases, and lessons** — the hook for Arabic ↔ English term mapping — with a course filter, progress-tinted nodes, and a drag-a-node/neighbors view; layer these onto `graphify` output rather than expecting them from it.
7. **Stack decision:** must be open source, free to use, simple and easy to develop, with a strong community. Research a real comparison — Next.js vs Astro vs Mintlify vs other current candidates — on simplicity, DX, license, community, **and total cost to run: static-first output is strongly preferred so the whole site rides a free hosting tier, with no paid service in the critical path**; verify each candidate's license rather than assuming (e.g., Mintlify may fail the open-source bar — that's a finding, not a blocker). The winner powers the platform, and the comparison is published as the platform's first blog post (the platform includes a blog).
8. **LLM-judged quality gates, wired into the test suite** (not one-off spot checks): every lesson paragraph is judged for (a) grounding in its source transcript and (b) aha-moment value; every quiz question is judged for placement, difficulty, and engagement; and every lesson must declare the tangible, reproducible skill it builds and give real practice on it — a lesson that only explains fails the rubric (see Pedagogical thesis). Define a **course rubric** aligned to current evidence-based pedagogy — Bloom's taxonomy, backward design, cognitive load theory, retrieval practice, worked examples — researched from the latest standards, not guessed.
9. **Cost-effective by design.** Prefer verified free/open-source tools and measure the total cost of accepted content: LLM usage, retries, graph/wiki extraction, local compute, storage/hosting, and human review. Reprocess from transcripts once, cache verified v1 work for later runs, and use tiered models (calibrated cheap/fast judges, premium reserved for generation, escalation, and sampled deep audits). Every released paragraph and quiz requires a valid verdict; sampling never replaces baseline coverage. Cache verdicts using content, source evidence, relevant context, rubric, prompt, model/settings, and schema/tool versions. Configure only authorized free-quota routes, stop after all are exhausted or remaining state is uncertain, bound per-request output/concurrency/retries, and report usage per accepted lesson across all providers and keys. Prefer deterministic SVG/HTML visuals over image-generation APIs. For v1, model tools use the approved zIDE/ZCode environments and an OpenAI-compatible adapter, initially with authorized Gemini free-tier quota; paid model usage needs a separate cash cap. Artifact hosting/operations must stay within the separate $5/month ceiling; cost savings must preserve the quality bar.
10. **Apple-grade quality control throughout v1.** Apply explicit gates to ingestion, transcript completeness, course design, lesson prose, assessments, diagrams, wiki/graph, rendering, and publication. Incomplete, failed, or unreviewed artifacts cannot be released. Use immutable sources, provenance, resumable execution, atomic release promotion, rollback, calibrated LLM evaluations, and human pilot review. Validate Arabic-first usability and behavior under failures and exhausted budgets; see the v1 acceptance contract.

**Settled for Content Factory v1:** OPTO 2311 — البصريات الهندسية in this repository; zIDE/ZCode model work through an OpenAI-compatible adapter, beginning with authorized Gemini free-tier quota and allowing explicitly approved compatible providers; no paid model usage without a separate cash cap; artifact hosting/operations capped at $5/month; Cloudflare Pages deployment. The goal is authoritative.

**Open decisions:** reviewer/learner availability, source rights and completeness, provider/key authorization and quota-reset evidence, quiz/wiki representation, calibrated evaluation thresholds, Arabic UI terminology, and the broader platform framework comparison.
